# 数据流与交叉验证：供主指南整合的草稿

本节依据当前 `train_overnight.py` 对应的 `dataset_overnight.py` 和 `cv_splits.py`。项目还有通用 `dataset.py`，其中保留其他增强和批次混合的实现；那些实现不代表当前夜间训练一定使用它们。

## 先把“样本”分成三个层级

- **患者（Patient）**：一个人，可以有多次检查。
- **检查（Study）**：某次检查，可以包含正位、侧位等多张图片。
- **图片（Image）**：CNN实际接收的一张图。CSV的一行对应一张图，同一Study的多张图共享十维标签。

标签不是一个类别编号。例如 `[1,0,1,0,0,0,0,0,0,0]` 表示第1和第3类同时阳性，其余类阴性。十个位置是十个“是否存在”问题；一个样本可以有多个1，也可以全为0。测试集没有标签时保留 `None`，不能冒充全0阴性。

## 一张胸片如何变成模型输入

```text
train_clean.csv（身份、相对路径、已验收SHA256、十维0/1标签）
             │
             ├─ 按五折计划选训练/内部验证Study，保留其全部图片
             │
             ▼
读取原始图片字节 → SHA256核对 → 解码 → EXIF方向摆正 → RGB
             │
             ▼
统一比例缩放到长边768 → 居中放入768×768黑色画布
             │
             ├─ 训练：随机水平翻转、轻微亮度/对比度、轻微旋转
             └─ 验证/测试：没有上述随机增强
             │
             ▼
Normalize → ToTensorV2 → CPU float32张量[3,768,768]
             │
             ▼
collate堆叠微批 → [2,3,768,768]，标签[2,10]
             │
             ▼
训练主进程搬到GPU → ConvNeXt V2-Base
```

**读原图和核对SHA。** 768输入直接从原图产生，不把300像素缓存放大。已经缩小的图丢掉了细节，插值不能把它们恢复出来。`file_sha256`是清洗验收时留下的文件字节指纹，读取时重新计算，发现图片被替换就报错。它只用于数据一致性检查，不是CNN提取的图像特征。

**方向和通道。** `ImageOps.exif_transpose`根据图片EXIF元数据摆正方向。`convert("RGB")`提供预训练模型要求的3通道接口；原图若是灰度，转换相当于把同一灰度复制到3个通道，不会凭空增加三种医学信息。代码遇到16位或浮点强度图会报错，要求先定义清晰的强度转换规则。

**等比缩放与Pad。** 假设原图宽1200、高900。统一倍率是 `768 / max(1200,900) = 0.64`，因此变为宽768、高576。它被放在768×768画布中，上下各补96像素黑边。两条轴共用同一倍率，胸廓不会因为强制拉成正方形而变形。长宽最终要取整，因此个别图片会有一个像素的边界差异。该步骤保留原图范围；后续训练的轻微旋转仍会产生黑色边角，并可能让非常靠边的像素移出画布，因此不要把“没有随机裁剪”讲成“任何增强都绝不会移动边界”。

**当前实际使用的增强。** 训练逐图抽样：50%水平翻转，50%小幅亮度/对比度变化（幅度上限0.10），30%在±5°内旋转。三种操作独立抽样，不保证每张图都执行。水平翻转的前提是当前标签不含左右侧别。验证和测试不随机增强，以免评估重复运行时输入变化。当前overnight路径没有Mixup、CutMix、高斯噪声或随机遮挡，通用 `dataset.py` 中虽有相关实现，也不能写进“正在使用”的流程。

**Normalize不是一层卷积。** 对每个像素通道执行 `x_normalized = (x / 255 - mean_channel) / std_channel`，使用ImageNet均值 `(0.485,0.456,0.406)` 和标准差 `(0.229,0.224,0.225)`。这是为了匹配预训练模型见过的输入数值尺度。黑边原来为0，归一化后变为负数，这是正常结果。它不等于把每张胸片单独拉到自己的均值0、方差1。

**张量形状是CNN入门的关键。** NumPy通常保存 `[H,W,C]=[768,768,3]`，PyTorch卷积层接收的单图形式是 `[C,H,W]=[3,768,768]`。`ToTensorV2`转换轴顺序，读取函数把dtype设为float32。`collate_overnight`再把2张图堆成 `[B,C,H,W]=[2,3,768,768]`。这里不把像素展平成上百万维向量，卷积网络将继续利用高和宽的邻接关系。CPU worker只负责读图和处理，模型计算由主进程在GPU完成。

## 两种权重不要混淆

`pos_weight`按类别计算，作用是提高某一疾病正样本漏判的代价；它来自当前折训练Study的正负计数，不应包含本折验证、官方验证或测试。

`loss_weight`按图片计算，作用是防止某次检查因为多拍几张就贡献更多总损失。若子集有N张图、S个Study，某Study有k张图，则每张权重是 `(N/S)/k`。这样每个Study所有图片的权重之和相同，且全体图片权重平均为1。例如6张图来自3个Study，其视角数为1、2、3；每张图分别赋权2、1、2/3，这三个Study的总权重都为2。它并没有把图拼接成一张图，也没有直接在训练前平均它们的特征。

## 为什么五折必须按患者和重复内容分组

五折并不是把“train、valid、test”混在一起重新洗牌。代码只把原始 `train_clean.csv` 划成5份。第0次用第0份验证、其余4份训练，之后轮换，得到每个训练Study都被一次未见过它的模型预测的OOF结果。官方valid仍为独立holdout，test不进入划分。五折训练有多份模型与更多计算代价，也不能保证必然比单折好；它让对验证结果的判断少依赖某一次划分，并提供折间集成候选模型。

如果把图片完全随机分开，同一个患者的两次检查、同一个Study的正侧位，甚至完全相同的图，都可能落在训练与验证两边。模型可能记住个体特征或图像内容，让验证分数过于乐观。

当前实现先把同患者所有Study绑在一起，再依据已验收的 `file_sha256` 和 `pixel_sha256` 把存在跨患者精确重复的患者连成更大组。若A与B重复，B与C重复，那么A/B/C必须整体同折。这是并查集表达的“连通分量”。它不把相似但不相同的胸片聚在一起，也不把组内标签改成同一个标签。然后先安排稀有阳性较多的大组，以贪心目标尽量平衡十类正例、十类负例，以及Study/患者/图片负载。因此各折图片张数未必严格相等。官方valid仅参与患者/Study/精确内容隔离检查，标签分布不用于这套分层统计。

一个容易读错的细节：内部CV验证图片原本来自train目录，记录中的 `split` 仍然是 `train`。它们的角色由折计划中的 `role='valid'` 决定，构造数据集时传 `training=False`，因此没有随机增强。这不是把内部验证当训练。

## 为什么先汇总概率，再找Study阈值

模型每张图输出十个logit，调用者逐维做一次sigmoid，得到十个概率。`aggregate_study_predictions`要求清单每张图恰好预测一次，按Study逐类求算术平均。如果同一次检查两张图对某类预测0.2和0.8，该Study该类概率为0.5。只拍一张的Study也只输出一行，因此Study级指标不会给多视角检查额外行权重。

不要写成“平均logit后sigmoid”：sigmoid是非线性的，两种运算顺序一般不等价。也不要在平均前对每张图做0/1判定；那会提前丢失概率强弱信息。均值之后才把Study概率交给后续阈值搜索和指标计算。阈值搜索的具体候选范围、优化指标与约束，应以 `threshold_search.py`、`train_overnight.py` 的实际调用为准。
