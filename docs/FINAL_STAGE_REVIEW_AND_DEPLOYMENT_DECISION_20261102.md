## 2. 蒸馏与早停的终局判断

A_base 在第 6 轮触发早停、最佳为第 1 轮。它从既有 Base 学生 E10 权重继续训练，
不是从头训练一轮就结束，也不是给当前 Tiny 生产软标签的教师。
冻结的软标签来自 024 五折 Base 教师（E20/12/12/12/12），按患者严格 OOF；本轮 Base 的退化不会改写这些缓存。

已核实 A_base E1→E6：训练硬标签 BCE 约 **0.407840→0.379493**，KD KL 约 **0.117695→0.133059**，
native 总体 AUC **0.809011→0.806459**、AP-only Study AUC **0.737627→0.734867**。
这支持“继续拟合训练硬标签时，验证排序退化，训练 KL 同时上升”的描述；没有据此测出验证集上的师生差异。
它不能单独证明是学习率过高、教师不可靠，或更长 patience 会修复问题。
实际调度还有一个具体不匹配：Base backbone 轮末 LR 从 E1 的 **4.99223e-6** 到 E6 的
**4.50980e-6**，只降低约 **9.7%**；按 25 轮安排的 cosine 在成熟权重迅速退化的前几轮仍接近峰值。
这是值得修正的机制线索，不是已经做过学习率消融的因果结论。

唯一较干净的历史 BCE/KD 对照为 Tiny512：

| 项目 | 实际 FP16 valid Macro-AUC |
| --- | ---: |
| Tiny512 直接 BCE | 0.803634677 |
| Tiny512 OOF KD | 0.805402258 |
| KD − BCE | +0.001767581 |
| 患者配对 95% 区间 | [-0.001751749, +0.005884143] |

结论：**未证实 KD 在该对照中稳定胜过 BCE，更没有证据证明它在当前 768 裁剪增强下存在明显优势。**
本轮四项都保留 KD，没有当前尺度的纯 BCE 控制；不能反向宣布 BCE 已胜出。
从 KD 成熟权重出发把 alpha 改成 0，是从 KD 权重初始化的 BCE-only 续训；
与继续 KD 配对时只能估计继续使用 KD 的增量，不是从 ImageNet 起点的纯 BCE 对照。

若未来另立续训实验，修复方向不是延长等待：先把 E0 未更新模型纳入评估和恢复候选，
避免“最好的其实是完全不继续训练”却被排除；学习率建议先在合规 train 内患者隔离实验中测试原峰值的 1/5，
例如 Tiny backbone 2e-6、Base backbone 1e-6，对应 head 2e-5/1e-5；最多 1 轮低幅 warmup，
再以预先固定的短续训窗口（例如 3–5 轮）单调 cosine 下降，而非复用 25 轮的慢衰减，
不重新升到旧峰值，不进行周期重启。patience 可用 2–3 个完整验证轮作为资源上限，始终恢复 best/E0；
它只减少浪费，不会治疗排序退化。不能因观察到当前结果就回写原 A/B 协议。

若从 ImageNet 重新训练，早期收敛过程和学习率需求不同，不能机械套用成熟权重的极低 LR 或短耐心。
新内部 CV 也不能从已经见过全 train 的学生初始化，或复用含有外层验证患者信息的 KD 教师缓存；
否则会再制造一次过拟合假象。当前行动计划不启动这种重训。

## 3. “局部看片”能否落地

**能实现一个低额外计算量的研究版本；目前不能作为已通过 100ms 的生产替代。**
明确选择“同一次 ConvNeXt 骨干前向＋保留全局头＋类别空间注意力头”，不选择默认中心裁剪。
固定中心区域可能丢肺尖、底部和外周征象；只有 Study 标签时，CAM 也可能定位文字或设备，不能作为病灶框真值。

算法：复用 `F[C,H,W]`；两个 1×1 投影分别给十类空间分数和 softmax 注意力，
局部分数为注意力加权和，以从 0 初始化的残差系数加入现有全局 logit，再 sigmoid。
监督仍作用于同 Study 的图像概率均值，不强制每个局部块阳性。
若 Tiny 的末级特征为预计的 768×24×24，两路投影约 **885 万 MAC/图/次前向**，无需另跑一次骨干；Study 图数和 hflip2 会成倍增加头部计算，不能把单图估算当作整组开销。
设计预算为在固定验收 Study 集上额外头 **平均 ≤1ms/Study 的目标**，它是需要实测的工程门槛，不是本轮实测或可保证的预测。

这条路线改变关注位置，**不能恢复 768 缩放时已经丢失的原始细节**。
若必须真放大原图 ROI，需要定位→原图取框→主模型的串行阶段；新 Study batch 能并行不同图片，
并不能消除每张图“先定位再分类”的依赖。多块各跑 768 还会增加骨干前向数。
在没有定位可靠性和额外时间预算证据前，本阶段不实施这些重型路线。
详见 [局部看片预研](LOCAL_REGION_READING_FEASIBILITY_20261102.md)。

### 4.2 新公告改变了什么

用户提供的官方计时样本 tar 已安全检查与解压，只有 28 张 JPEG、15 个 Study，没有计时脚本或 README。

本报告本地预览沿用 5 Study 预热、3 轮，明确不等于官方正式验收。

对于有 N 张图的 Study：

```text
逐图串行：T_serial(N) = Σ[读取＋解码＋缩放] + N×GPU单图前向 + 聚合/写出
Study批量：T_batch(N) = Σ[读取＋解码＋缩放] + GPU批量前向(N) + 聚合/写出
```

双模型＋hflip2 当前是逐图四次骨干调用；按 Study 批量后是每 Study 四次 N 图调用，

### 4.3 TensorRT：不承诺端到端 2–3 倍

设解码/I/O/预处理等无法被 TRT 加速的时间占比为 f，GPU 前向快 s 倍，则整体加速至多
`1 / (f + (1-f)/s)`。例如 f=0.5 时，GPU 快 2 倍/3 倍只对应总计 **1.33 倍/1.50 倍**；
这是条件算例，不是对当前 GPU 的测量。即使 GPU 无限快，总加速也不超过 `1/f`。
预先做可行性预算时，可保守按 GPU 前向 1.5 倍加速做情景分析，不把 2–3 倍当成前提；这也不是实测预测。
新规使同 Study 批处理合法，不能据此保证 Tiny/Base/TTA 总时间仍低于 100ms。

工程上把 045 进一步降至 100ms，需要同时关注两个具体环节：先在计时窗口内按同 Study
用固定小型 CPU 线程池解码不同图，限制原生 resize 的内层线程，避免线程数相乘；保持每张图的解码与等比缩放结果不变。
再用 TensorRT 合并 LayerNorm/GELU/卷积相关算子和内存调度，预分配 pinned buffer 与 GPU 输入输出，
按固定 N profile 重用执行上下文。是否把原图/hflip 合成 2N batch 只在数值与显存验收后决定，不能默认一定更快。
这是同一条冻结部署优化主线的 CPU/GPU 两部分，不增加模型训练或新的医学裁剪。
以当前 163.80ms 作情景预算，若 GPU 恰好快 2 倍，要到 100ms，非 GPU 占比须低于约 22.1%；
若 GPU 快 3 倍，该占比须低于约 41.6%。若分段测量不满足，就必须同时压缩 CPU 开销，不能只等待 TRT 奇迹。

可执行实现是从**冻结权重**导出 ONNX，并在官方环境中分别构建 FP16 TensorRT 引擎；
保持 768 输入、原归一化、logits→FP32 sigmoid、原 TTA/成员融合以及 Study FP64 累积顺序。
动态 batch 按同 Study 图数，预设有限形状 profile，过大 Study 依固定策略分块而不丢图。
先不做 INT8，也不将每 Study 自适应早退混入本轮候选。

ONNX 导出与解析应实际检查 ConvNeXt 的 LayerNorm、GELU、动态形状支持和可能的 fallback，
不能仅凭“已装 TRT”认定整网已加速。2080Ti 和 T4 都属 SM75 不代表 engine 无条件可移植，
最终在目标 T4 构建并验收。引擎与所有实际调用资产还须满足既有 500MB 约束。
批量与 TRT 都可能改变数值；必须用完整 valid 检查 AUC、逐图/Study 概率、概率排序和二值判定，
改变概率的实现要作为新部署候选冻结，不能冒称旧 CSV 等值替换。
