# 平台退分后的第二次审查与执行决定

2026-11-05，香港时间。用户本轮提供了四份CSV的实际平台展示成绩，要求以真实提交成绩为目标，并在无效时停止当前训练。以下分数由用户报告，文件身份由本地SHA256核对；没有访问平台后台或测试标签。

**执行决定：继续当前DINO训练，撤销“只凭开发集整体AUC上涨就足以晋级提交”的判断。当前模型仍在第一轮，既没有完整开发结果，也没有数值/代码失败证据；现在停掉只是另一次没有验证结果的换方向。当前80%训练量的模型属于研究候选，不能直接作为已证实能超过76.92的最终submission。**

平台主指标本来就是隐藏测试集的十类Macro-AUC。需要改进的是泛化与选择证据，而不是换成一个与比赛无关的优化指标。任何人现在声称DINO一定超过76.92，都没有相应的测试标签或平台结果支持。

**当前方案有一个必须承认的不足：新开发集虽然大，却仍主要复制train患者构成。** 至少5次检查患者贡献的Study占比：train18.51%、新开发集17.88%、official valid66.47%；至少10次检查分别3.45%、3.46%、47.61%。这类患者并非简单多几次重复记录：train中一次检查患者“无异常”比例52.43%，至少5次检查患者只有17.95%；AP-only比例相应从33.13%上升到74.20%，平均阳性疾病数从0.838上升到1.779。

因此，“换成2211名患者的dev”主要改善样本量和独立性，不能自动保证对反复就诊、AP胸片、多病共存病例的迁移能力。上一份方案对这一点强调不够，现予补正。≥10次检查的dev只有11名患者，类1阳性患者仅4人，不能用这一个很小的切片硬早停或调整系数。

## 后续决策如何直接服务提交

1. **继续当前有界训练，不重启、不换种子制造新的偶然高分。** 原18轮上限、至少8轮、patience5照常；数值/运行故障另按真实证据处理。首轮loss下降不等于测试涨分。
2. **整体改善不再足以交付。** 与同折旧CNN比较总体、AP/单图、反复检查患者及置信区间；必须检查收益是否来自容易病例、是否有稳定困难场景退化。小切片不因一次点值下降就一票否决，多个相关切片也不冒称多个独立验证集。
3. **先跨患者折复验，再投入最终重训。** 若当前候选在完成预算后既无单模型改善、也没有待独立验证的互补证据，则淘汰该分支，不因DINO名字继续追加计算。新折模型必须重新从通用公开初始化训练，禁止把旧fold4选好的权重直接当另一折无泄漏起点。
4. **当前80%模型不直接替换76.92成果。** 通过复验后冻结配方、轮数、全类别统一的有限融合选择，再完整train重训。若选择将官方valid作为额外有标签训练数据，须先冻结全部选择，合并后不再用valid早停/选checkpoint/调参；这是规则允许、可利用额外困难病例标签的后期步骤，不是当前后台已经执行的操作。
5. **模型失败后的替代实验须针对已证实的train/valid困难病例。** 优先单因素检查train内部的AP/反复检查病例采样与优化、或高分辨率保留细节；仅在独立折成立时纳入。不能按test病例比例重加权，也不把增加模型数当可靠收益。

最终采用的依据是可复现的泛化证据和合规的最终提交评分；不能提供“尚未训练完却必定超过76.92”的保证。明确行动是继续当前实验、补齐缺失的同折与困难病例验证、保护已有最好成果，而不是再次仅按一个本地AUC数字换CSV。
